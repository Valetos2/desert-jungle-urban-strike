# Jungle DOS → Genesis: первое сопоставление объектов

16 ноября 2026. ROM не менялся. Скрипт compare_object_positions.py и отчёт object_correspondence.json.

## Устройство начала LEVEL

В начале файла лежат uint16 LE смещения списков секторов. Нулевое смещение означает отсутствие списка. По ненулевому смещению: uint16 число элементов, затем столько же uint16 смещений записей объектов внутри LEVEL. Все извлечённые ссылки проверены на попадание в файл. Для миссий1–9 число секторов соответствует заголовкам Genesis; для A принято70 по размеру карты и согласованной структуре начала файла. Это статическое декодирование, без трассировки DOS-загрузчика.

В записях сопоставлены поля +4,+6,+8,+10 (границы), +16,+18 (позиция), +20 (параметр неизвестного назначения). DOS хранит слова little endian, Genesis — big endian. Например, запись LEVEL2+0x8C соответствует ROM+0x197F16: границы (55,81,59,84), позиция (457,658), параметр10. Названия осей Y/X следуют прежней модели Genesis, самостоятельная проверка ориентации в DOS ещё нужна.

## Десятая миссия

Из70 секторных списков извлечено95 уникальных записей, каждая встретилась один раз. Это записи, доступные через начальную таблицу, а НЕ гарантированно все объекты уровня: дополнительные могут создаваться сценариями. В JSON сохранены смещения, номера секторов, границы, позиции и неинтерпретированные поля20/22.

На однозначных совпадениях обычных уровней построена предварительная связь первого32-битного поля записи DOS с первым32-битным полем Genesis (кандидаты на указатели описателей). Для66 из95 записей LEVELA найден единственный кандидат описателя Genesis. Для29 соответствие пока отсутствует. Это не готовый конвертер: нужно проверить назначение описателя, дополнительные поля, код поведения и команды после записи.

Важное отличие: указатели нельзя переносить прямой перестановкой байтов. Например, у пары LEVEL2+0x8C / ROM+0x197F16 первый указатель меняется с DOS0x4B1BB844 на Genesis0x109E3C. Другие адреса и часть полей также устроены по-разному.

## Следующие шаги

1. Привязать описатели к названиям графики и поведению; разобрать29 пока не сопоставленных записей десятой миссии.
2. Разобрать последовательности после основной части записи: связи, динамическое появление, маршруты, условия заданий.
3. Проверить, какими полями задаются глубина погружения корабля и допустимость его уничтожения.
4. Затем собирать конвертер записей; только после проверки сценариев — экспериментальный ROM.

Скрипт проверяет SHA256 исходного Genesis ROM. В репозиторий записаны только аналитические результаты и код; оригинальные LEVEL/ROM не включены.
