# Jungle Strike · Eco Threat · Flight TEST v4

В главном меню номер и название десятой кампании занимают одну строку. В паузе кнопка B открывает карточку задания. Стрелки переключают восемь заданий. Сначала видна только первая карточка. По мере выполнения заданий штатная процедура из Return Home раскрывает следующую. Английские названия, короткие и полные описания взяты из DOS FLICDATA. На вкладке STATUS используются счётчики Eco Threat.

Это сборка для облёта. Сценарные цели и противники ещё в работе, поэтому в обычном полёте выполнить первое задание пока нельзя. Для проверки раскрытия тест меняет счётчики в памяти эмулятора, затем открывает настоящую паузу. В поставляемом ROM специального переключателя для раскрытия заданий нет.

## Графика

Для каждой из 47 записей взят левый верхний угол из DOS LEVELA (+4, +6). Ширина и высота считываются из Genesis-описателя конкретного рисунка. Прежнее независимое округление координат противоположных краёв увеличивало некоторые прямоугольники на один тайл и заставляло игру читать за концом строки рисунка. Физические координаты объекта хранятся отдельно. Например, у дерева №36 изображение начинается на 78 пикселей ниже указанной физической точки.

Площадка №42 пересекает вертикальный и горизонтальный швы кольцевой таблицы VDP. Обработчик для платформы Eco Threat делит вывод на прямоугольники внутри страницы, сохраняя смещения рисунка и карты столкновений. Для проверки на однотонном фоне тест запускает игру с камерой около каждого объекта, проверяет тайлы в VRAM и сравнивает таблицу вывода с описателем ROM по мировым координатам. На приложенной иллюстрации слева кадры v3, справа v4.

## Запуск и сборка

Начать новую игру через Campaign после сброса. В архиве полный тестовый ROM и IPS для чистого Jungle Strike с SHA-1 7a7568e39341b1bb218280ee05c2b37c273317b5. Проверка проводилась в Genesis Plus GX.

Из корня проекта выполнить python strike_work/eco_flight_v4/build.py. Нужны собранный v3, файлы DOS LEVELA и FLICDATA и отчёты предыдущих этапов. Для графической проверки выполнить donor.py (нужно состояние из v2), затем validate.py НОМЕР_ОБЪЕКТА 4. Без аргументов validate.py проверяет все стадии раскрытия меню. Для подготовки иллюстрации вызвать validate.py для каждого из F165–F168 и F174 с версией 3 и 4, затем gallery.py и package.py. Сборщик содержит байты обработчика из wrap.asm.
